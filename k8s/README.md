# ShopFast on Kubernetes

This directory contains the complete Kubernetes migration for ShopFast (see
[`Kubernetes_Migration_Plan.md`](../../Kubernetes_Migration_Plan.md)). It is a
Kustomize-based layout with `dev` and `prod` overlays, ready to apply to a local
cluster (minikube/Docker Desktop) or a production cluster via Argo CD.

## Layout

```
k8s/
  base/            Namespace, ConfigMap, Secret, ResourceQuota, LimitRange,
                  NetworkPolicies (deny-by-default), ServiceMonitor.
    secrets/       The shopfast-secrets Secret (dev only; excluded in prod).
  infra/           Stateful backing services: PostgreSQL, Redis, Kafka +
                  Zookeeper, Elasticsearch, Keycloak (+ realm ConfigMap).
  services/        eureka-server, api-gateway, the 14 business microservices,
                  frontend, and HPAs. Generated by scripts/gen-k8s-services.py.
  ingress/         Ingress + cert-manager TLS for shopfast.live / shopfast_test.live.
  overlays/
    dev/           Local/dev overlay. Apply with: kubectl apply -k k8s/overlays/dev
    prod/          Production overlay synced by Argo CD. Uses Let's Encrypt and
                  External Secrets instead of the raw Secret.
```

## Prerequisites

- A cluster with **ingress-nginx** and **cert-manager** installed.
  ```bash
  helm repo add ingress-nginx https://kubernetes.github.io/ingress-nginx
  helm install ingress-nginx ingress-nginx/ingress-nginx -n ingress-nginx --create-namespace
  helm repo add jetstack https://charts.jetstack.io
  helm install cert-manager jetstack/cert-manager -n cert-manager --create-namespace \
    --set crds.enabled=true
  ```
- `metrics-server` for the HPAs (minikube: `minikube addons enable metrics-server`).
- `kubectl` / `kustomize`.

## Build & deploy

```bash
# 1. Build + tag images by git SHA (scripts/build-images.sh)
./scripts/build-images.sh ghcr.io/shopfast push

# 2. Generate real secrets (do NOT commit the output)
./scripts/generate-secrets.sh

# 3. Apply dev
kubectl apply -k k8s/overlays/dev

# 4. Or use the deploy helper
./scripts/deploy.sh dev
```

## Migration order (plan section 13)

1. `base/` — namespace, config, secrets, quotas, network policies
2. `infra/` — postgres, redis, kafka, elasticsearch, keycloak
3. eureka + api-gateway
4. leaf services (product, category, user, auth)
5. order / cart / payment / notification flow
6. frontend + ingress + TLS
7. observability (ServiceMonitor) + HPA + NetworkPolicies
8. CI/CD + Argo CD + prod overlay

## Regenerating service manifests

`k8s/services/*.yaml` for the 14 business services are generated from a data
table so they stay consistent (same probes, security context, env injection).
To add or change a service, edit `scripts/gen-k8s-services.py` and re-run:

```bash
python3 scripts/gen-k8s-services.py
```

eureka-server, api-gateway, frontend, and hpa.yaml are hand-written because they
differ from the template.

## Secrets

The dev `base/secrets/secrets.yaml` contains **placeholders only**. For real
deployments use SealedSecrets or the External Secrets Operator — see
`base/sealed-secret-example.yaml`. The prod overlay deliberately omits the raw
Secret so it can be supplied by the cluster's secret store.

## Notes / deviations from docker-compose

- Images are referenced as `ghcr.io/shopfast/<svc>:<tag>` (git SHA in prod) instead
  of `:latest`, per the plan's image strategy.
- Service discovery keeps Eureka initially (per the plan's low-risk first step);
  services reach each other via `<svc>.shopfast.svc.cluster.local`.
- Keycloak runs `start-dev` inside the cluster (plain HTTP, behind the Ingress);
  switch to `start` + TLS for production.
- Elasticsearch runs with security disabled to match the current compose topology;
  enable xpack security for production.
